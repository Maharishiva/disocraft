Gradients of Gradients

How DeepMind's DiscoRL actually trains its meta-network — second-order autodiff, KL targets, mixed-mode differentiation, and a 200-line toy you can run on a laptop.

Fred  ·  June 2026  ·  ~50 min read  ·  companion code: blog/toy_discorl.py

TL;DR — DiscoRL (Oh et al., Nature 648, 2025) meta-learns an RL update rule that beats MuZero on Atari and generalizes to unseen benchmarks. Most readers get the architecture; far fewer get the training. The meta-network is trained by backpropagating through the agent's own gradient-descent updates: the agent's parameter update is itself a differentiable function of the meta-parameters, so "how good the agent became" can be differentiated with respect to "the rule that taught it".

That requires second-order derivatives (Hessian-vector and mixed-derivative products), which is what "gradients through gradients" means; it is made affordable at scale by MixFlow-MG, a mixed-mode (forward-over-reverse) autodiff trick that exploits the symmetry of second derivatives to cut memory by >10×. The rule outputs targets matched with a KL divergence rather than a scalar loss because targets-plus-distance is a strictly larger search space (it contains semi-gradient methods like Q-learning, which are not the gradient of any loss) and because KL on softmax-normalized vectors gives bounded, well-conditioned gradients that keep meta-optimization stable.

This post derives all of it, walks the actual released code, and meta-trains a tiny discovered rule from scratch — which ends up beating tuned REINFORCE on its toy world.

1Why this post

I've spent the last while reproducing DiscoRL's Disco103 rule on Craftax-Classic (pixels): load DeepMind's released meta-network weights, train a fresh agent with the discovered update rule, and watch it reach a ~12 episode return at around 12M environment steps — a Crafter-style score in the neighbourhood of the paper's Crafter results (Craftax is a separate reimplementation, so the numbers aren't directly comparable, but the rule plainly works on a world it never saw during discovery). That exercise convinces you the discovered rule is real. It does not tell you how the rule was discovered.

The Nature paper compresses the entire meta-training machinery into one line:

$$ J(\eta) = \mathbb{E}_{\mathcal{E}}\,\mathbb{E}_{\theta}\!\left[J(\theta)\right], \qquad \nabla_\eta J(\eta) \;\approx\; \mathbb{E}_{\mathcal{E}}\,\mathbb{E}_{\theta}\!\left[\,\nabla_\eta\theta\;\nabla_\theta J(\theta)\,\right] $$

That innocent \(\nabla_\eta \theta\) is doing a colossal amount of work. It hides an unrolled optimization process, second-order derivatives, a clever estimator for a term you can't backpropagate through, half a dozen stabilization tricks, and a memory problem severe enough that DeepMind wrote a separate ICML paper (MixFlow-MG) just to make it fit on TPUs. This post unpacks all of it, with the math, the JAX mechanics, and a minimal re-implementation that actually runs.

Everything here is grounded in three primary sources: the Nature paper itself, the open-sourced disco_rl repository (including the official meta_train.ipynb colab, which contains a simplified but real version of the outer loop), and the MixFlow-MG paper (Kemaev et al., ICML 2025).

2The cast, in five tensors

Quick recap to fix notation — skip ahead if the architecture is already burned into your retinas.

The agent, parameterized by \(\theta\), looks at an observation and emits five things:

The meta-network — the thing that is the RL algorithm — is a function \(m_\eta\) that consumes a trajectory of the agent's outputs from time \(t\) to \(t+n\), plus rewards and termination flags, and emits targets:

$$ m_\eta:\; \big(f_\theta(s_t),\,a_t,\,r_t,\,\dots,\,f_\theta(s_{t+n}),\,f_{\theta^-}(s_{t+n})\big) \;\longmapsto\; \big(\hat\pi_t,\,\hat y_t,\,\hat z_t\big) $$

where \(f_\theta = (\pi_\theta, y_\theta, z_\theta, q_\theta)\) and \(\theta^-\) is an exponential moving average of \(\theta\) (a target network). Architecturally it's surprisingly small: in the released Disco103 weights, the core is an LSTM with 256 hidden units that scans the trajectory backwards in time (so information from the future flows into the targets of the present — that's how multi-step bootstrapping like TD(\(\lambda\)) becomes expressible), with tiny shared MLPs embedding \(y\) and \(z\), shared 1-D convolutions over the action axis (so the same rule works for any number of actions), and a second, slower "lifetime" LSTM of 128 units that takes one step per agent update, letting the rule adapt to where the agent is in its life.

The agent is then trained, at every update, on the loss

$$ L(\theta) = \mathbb{E}_{s,a\sim\pi_\theta}\Big[ D\big(\hat\pi,\,\pi_\theta(s)\big) + D\big(\hat y,\,y_\theta(s)\big) + D\big(\hat z,\,z_\theta(s,a)\big) + L_{\text{aux}} \Big], \qquad D = \mathrm{KL}, $$

where every vector is pushed through a softmax before the KL, and \(L_{\text{aux}} = D(\hat q, q_\theta(s,a)) + D(\hat p, p_\theta(s,a))\) trains the two predefined heads (\(\hat q\) is a Retrace return projected to a two-hot categorical over 601 bins; \(\hat p\) is the policy at the next state). In the released code the weights are \(1.0\) for the \(\pi\)/\(y\)/\(z\)/\(p\) terms and \(0.2\) for the value term.

So far, so familiar. Now the actual question: where does \(\eta\) come from?

3Two nested loops: discovery as bilevel optimization

Discovery is a bilevel optimization problem. The inner loop is ordinary agent training, except the loss is dictated by \(\eta\):

$$ \theta_{k+1} \;=\; \theta_k - \alpha\, U\!\big(\nabla_\theta L(\theta_k, \eta;\, \mathcal{D}_k)\big) \qquad k = 0,1,\dots $$

(\(U\) is the optimizer — Adam in the real system — and \(\mathcal{D}_k\) the \(k\)-th batch of trajectories, 90% of which come from replay.) The outer loop adjusts \(\eta\) to maximize how much reward agents trained this way collect over their lifetimes:

$$ \max_\eta\; J(\eta) = \mathbb{E}_{\mathcal{E}\sim p(\mathcal{E})}\;\mathbb{E}_{\theta_0} \Big[\, J\big(\theta_K(\eta)\big) \Big], \qquad J(\theta) = \mathbb{E}_{\pi_\theta}\Big[\textstyle\sum_t \gamma^t r_t\Big]. $$

The crucial design decision: the outer loop is optimized by gradient ascent, not evolution. This is what lets DiscoRL search a space with millions of meta-parameters (a whole LSTM network) instead of the handful of hyperparameters or short symbolic programs that evolutionary approaches can handle. But it forces you to answer an uncomfortable question — what is the gradient of "the agent got better over its lifetime" with respect to "the weights of the network that produced its training targets"? By the chain rule:

$$ \nabla_\eta J(\eta) \;\approx\; \mathbb{E}\Big[\; \underbrace{\nabla_\eta \theta_K}_{\substack{\text{how meta-params moved}\\\text{the agent's params}\\\text{(backprop through updates)}}} \;\cdot\; \underbrace{\nabla_\theta J(\theta_K)}_{\substack{\text{how agent params}\\\text{affect return}\\\text{(actor-critic estimate)}}} \;\Big] $$

The two factors have completely different characters, and the system computes them in completely different ways:

  • \(\nabla_\theta J(\theta)\) involves the environment, which you cannot backprop through. It is estimated, with a standard policy-gradient estimator (more in §4.4).
  • \(\nabla_\eta \theta\) involves only the agent's update procedure — which is pure JAX code: rollout in, loss, gradient, Adam, parameter delta out. It is computed exactly, by backpropagating through that code. Including through the gradient computation inside it.

That second bullet is the heart of everything. Let's slow way down.

4"Gradients through gradients", from scratch

4.1 A one-dimensional toy you can do on paper

Strip everything away. One agent parameter \(\theta\) (a single number — think of it as the student's belief), one meta parameter \(\eta\) (also a single number — the teacher's knob). The "meta-network" just outputs \(\eta\) itself as the target, and the agent loss is half the squared distance between the student and the target:

$$ L(\theta, \eta) = \tfrac12(\theta - \eta)^2 . $$

The agent starts from a fixed initialization \(\theta_0\) and takes one SGD step with learning rate \(\alpha\):

$$ \theta_1 \;=\; \theta_0 - \alpha\,\frac{\partial L}{\partial \theta}(\theta_0,\eta). $$

After training, the "environment" pays off according to \(J(\theta) = -(\theta - \theta^\star)^2\): the closer the trained student lands to the sweet spot \(\theta^\star\), the better. The meta-question: should the teacher raise or lower the target \(\eta\)? The answer is the sign of the meta-gradient \(dJ/d\eta\) — so let's compute it with no skipped steps.

Step 0 — who depends on whom

Before touching any derivative, draw the dependency structure; every calculus mistake in meta-learning is really a dependency mistake. The quantities are: \(\eta\) (the free knob we'll differentiate with respect to); \(\theta_0\) (a constant — the initialization was chosen before the teacher had any say, so it does not move when \(\eta\) moves); \(\theta_1\) (depends on \(\eta\), through the update); and \(J(\theta_1)\) (depends on \(\eta\) only through \(\theta_1\)).

The toolbox — the five facts of calculus this whole post runs on:
  1. Constant rule. If \(c\) does not depend on \(\eta\), then \(\frac{dc}{d\eta}=0\).
  2. Linearity. \(\frac{d}{d\eta}\big(u + c\,v\big) = \frac{du}{d\eta} + c\,\frac{dv}{d\eta}\) — derivatives pass through sums, and multiplicative constants slide out front.
  3. Chain rule. For a composition \(J\big(\theta_1(\eta)\big)\): \(\;\frac{dJ}{d\eta} = J'\big(\theta_1\big)\cdot\frac{d\theta_1}{d\eta}\) — derivative of the outer function, evaluated at the inner value, times derivative of the inner function. (The prime means "derivative of \(J\) with respect to its only argument": \(J'(\theta) \equiv \frac{dJ}{d\theta}\).)
  4. Partial vs. total. \(\frac{\partial}{\partial\theta}\) means "wiggle \(\theta\) while holding every other symbol frozen". \(\frac{d}{d\eta}\) means "wiggle \(\eta\) and follow every arrow in the dependency graph through which \(\eta\) sneaks in". For a function with two slots, \(g(\theta, \eta)\), where the first slot may itself depend on \(\eta\), the total derivative adds one term per slot (this is the multivariable chain rule): $$\frac{d}{d\eta}\,g\big(\theta(\eta),\,\eta\big) = \underbrace{\frac{\partial g}{\partial \theta}\cdot\frac{d\theta}{d\eta}}_{\text{path through slot 1}} \;+\; \underbrace{\frac{\partial g}{\partial \eta}\cdot 1}_{\text{path through slot 2}}$$
  5. A derivative is just another function. \(g(\theta,\eta) := \frac{\partial L}{\partial \theta}(\theta,\eta)\) is an ordinary function of two variables, and nothing stops us from differentiating it again. Doing so produces second derivatives. Notation: \(\frac{\partial^2 L}{\partial\eta\,\partial\theta}\) means \(\frac{\partial}{\partial\eta}\Big(\frac{\partial L}{\partial\theta}\Big)\) — read the denominator right-to-left: the \(\theta\)-derivative was taken first, then the \(\eta\)-derivative. (For any smooth \(L\), Schwarz's theorem says the order doesn't matter: \(\frac{\partial^2 L}{\partial\eta\,\partial\theta} = \frac{\partial^2 L}{\partial\theta\,\partial\eta}\). File that away — it becomes the punchline of §6.)

Step 1 — compute the inner gradient (the slope the student feels)

$$ g(\theta, \eta) \;:=\; \frac{\partial L}{\partial \theta} \;=\; \frac{\partial}{\partial\theta}\,\tfrac12(\theta-\eta)^2 \;=\; (\theta - \eta)\cdot\underbrace{\frac{\partial(\theta-\eta)}{\partial\theta}}_{=\;1} \;=\; \theta - \eta . $$

(Chain rule on the square; \(\eta\) stays frozen because this is a partial derivative in \(\theta\).) While we're here, note for later how this slope reacts to the target:

$$ \frac{\partial^2 L}{\partial\eta\,\partial\theta} \;=\; \frac{\partial g}{\partial \eta} \;=\; \frac{\partial}{\partial\eta}\,(\theta - \eta) \;=\; -1 . $$

In words: raising the target by \(\varepsilon\) lowers the slope by \(\varepsilon\). That is the teacher's entire mechanism of influence — the only way \(\eta\) touches the student is by tilting the loss surface the student slides down.

Step 2 — write the update as an explicit function of \(\eta\)

$$ \theta_1(\eta) \;=\; \theta_0 - \alpha\, g(\theta_0, \eta) \;=\; \theta_0 - \alpha(\theta_0 - \eta). $$

Step 3 — differentiate the update (two routes, same answer)

Route A: substitute first, then differentiate. In this toy we have \(\theta_1\) in closed form, so just take \(\frac{d}{d\eta}\) term by term:

$$ \frac{d\theta_1}{d\eta} = \underbrace{\frac{d\theta_0}{d\eta}}_{=\,0\ \text{(constant rule)}} -\;\alpha\,\underbrace{\frac{d(\theta_0-\eta)}{d\eta}}_{=\,0\,-\,1\ \text{(linearity)}} =\; 0 - \alpha\cdot(-1) \;=\; \alpha . $$

Done: \(\frac{d\theta_1}{d\eta} = \alpha\). Raise the target by \(\varepsilon\) and the student lands higher by \(\alpha\,\varepsilon\). Which makes sense: one SGD step moves the student a fraction \(\alpha\) of the way toward the target.

Route B: differentiate the update rule symbolically, without substituting. This is the route that matters, because in the real system \(L\) is a deep network's loss and you never get a closed form. Keep \(g\) abstract and apply the toolbox rules one at a time:

$$ \frac{d\theta_1}{d\eta} = \frac{d}{d\eta}\Big[\theta_0 - \alpha\, g(\theta_0, \eta)\Big] = \underbrace{\frac{d\theta_0}{d\eta}}_{=\,0} -\;\alpha\,\frac{d}{d\eta}\,g(\theta_0, \eta) \qquad\text{(linearity + constant rule)} $$

Now the key move. \(g\) has two slots, so toolbox rule 4 (total derivative) gives one term per slot:

$$ \frac{d}{d\eta}\,g(\theta_0, \eta) = \underbrace{\frac{\partial g}{\partial\theta}\cdot\frac{d\theta_0}{d\eta}}_{=\;\frac{\partial g}{\partial\theta}\,\cdot\, 0\;=\;0} +\; \underbrace{\frac{\partial g}{\partial\eta}\cdot\frac{d\eta}{d\eta}}_{=\;\frac{\partial g}{\partial\eta}\,\cdot\, 1} =\; \frac{\partial g}{\partial \eta} \;=\; \frac{\partial^2 L}{\partial\eta\,\partial\theta}\bigg|_{(\theta_0,\,\eta)} . $$

The first slot contributes nothing only because \(\theta_0\) is the initialization — after one more inner step that slot comes alive (Step 6). The vertical bar means "evaluated at the point \((\theta_0, \eta)\)": a second derivative is still a function, so you must say where you are reading it off. Putting Route B together:

$$ \boxed{\; \frac{d\theta_1}{d\eta} \;=\; -\,\alpha\;\frac{\partial^2 L}{\partial\eta\,\partial\theta}\bigg|_{(\theta_0,\,\eta)} \;} \qquad\text{for our } L:\;\; -\alpha\cdot(-1) = \alpha\;\;\checkmark\ \text{(matches Route A)} $$

Look at what just happened. The update contains a first derivative (\(g = \partial L/\partial\theta\)). Differentiating the update therefore manufactures a second derivative — the mixed one, \(\partial^2 L/\partial\eta\,\partial\theta\): "how does moving the teacher's knob change the slope the student feels". No mysticism. "Gradient through gradients" is the literal, mechanical consequence of applying \(\frac{d}{d\eta}\) to a formula that already has a \(\frac{\partial}{\partial\theta}\) inside it.

Step 4 — chain rule up to the reward

\(J(\theta) = -(\theta-\theta^\star)^2\), so \(J'(\theta) = -2(\theta - \theta^\star)\) (chain rule on the square again; \(\theta^\star\) is a constant). Toolbox rule 3 on the composition \(J\big(\theta_1(\eta)\big)\):

$$ \frac{dJ}{d\eta} \;=\; J'(\theta_1)\cdot \frac{d\theta_1}{d\eta} \;=\; \underbrace{-2(\theta_1 - \theta^\star)}_{\substack{\text{how the reward reacts}\\\text{to the landing spot}}} \;\cdot\; \underbrace{\Big(\!-\alpha\,\frac{\partial^2 L}{\partial\eta\,\partial\theta}\Big)}_{\substack{\text{how the knob moves}\\\text{the landing spot}\;=\;\alpha}} \;=\; -2(\theta_1-\theta^\star)\,\alpha . $$

Step 5 — numbers, and a no-calculus sanity check

Take \(\theta_0=0\), \(\eta=1\), \(\alpha=0.3\), \(\theta^\star=2\). Then the slope is \(g(\theta_0,\eta) = 0 - 1 = -1\), the student lands at \(\theta_1 = 0 - 0.3\cdot(-1) = 0.3\), and

$$ \frac{dJ}{d\eta} = -2\,(0.3 - 2)\cdot 0.3 = (3.4)(0.3) = +1.02 \quad\Longrightarrow\quad \text{positive — raise the target.} $$

If you don't fully trust the symbol-pushing, do what a derivative is: bump the knob and watch what happens. A derivative is nothing but the last column of this table in the limit of an infinitely small bump:

teacher's knob \(\eta\)student lands at \(\theta_1 = 0.7\,\theta_0 + 0.3\,\eta\)reward \(J(\theta_1)\)\(\Delta J / \Delta\eta\)

(The finite-difference value isn't exactly 1.02 at a finite bump size because \(J\) is curved; it converges to 1.02 as the bump shrinks. Autodiff computes that limit exactly, in one pass, without ever bumping anything.)

Step 6 — take one more inner step, and watch the Hessian get born

Everything above had a simplification hiding in it: \(\theta_0\) was a constant, so the "path through slot 1" died at birth. Take a second SGD step and it wakes up:

$$ \theta_2 = \theta_1 - \alpha\, g(\theta_1, \eta), \qquad\text{where now } \theta_1 = \theta_1(\eta)\ \text{moves with } \eta . $$

Differentiate with toolbox rule 4 — this time both slots of \(g\) are alive:

$$ \frac{d\theta_2}{d\eta} = \frac{d\theta_1}{d\eta} - \alpha\Bigg[ \underbrace{\frac{\partial g}{\partial\theta}\bigg|_{\theta_1}\!\cdot\frac{d\theta_1}{d\eta}}_{\substack{\text{slot 1: }\eta\text{ already moved }\theta_1,\\\text{which changes the slope}}} + \underbrace{\frac{\partial g}{\partial\eta}\bigg|_{\theta_1}}_{\substack{\text{slot 2: }\eta\text{ tilts}\\\text{the loss directly}}} \Bigg] $$

and since \(\frac{\partial g}{\partial \theta} = \frac{\partial^2 L}{\partial\theta^2}\) — the Hessian, the curvature of the loss in \(\theta\) — this rearranges to

$$ \frac{d\theta_2}{d\eta} = \Big(1 - \alpha\,\frac{\partial^2 L}{\partial\theta^2}\Big)\,\frac{d\theta_1}{d\eta} \;-\; \alpha\,\frac{\partial^2 L}{\partial\eta\,\partial\theta}\bigg|_{\theta_1} . $$

For our \(L\): \(\partial^2 L/\partial\theta^2 = \partial(\theta-\eta)/\partial\theta = 1\), so \(\frac{d\theta_2}{d\eta} = (1-0.3)(0.3) + 0.3 = 0.51\). The structure is the point:

The shape of every meta-gradient — (decay factor from curvature) × (sensitivity inherited from previous steps) + (fresh injection from this step's targets). Iterate it \(N\) times and you get exactly the recursion of §4.2, with the scalars promoted to matrices: the curvature \(\partial^2 L/\partial\theta^2\) becomes the Hessian matrix \(H_k\), the mixed derivative becomes the matrix \(C_k\), and \(1\) becomes the identity \(I\). If Step 6 makes sense, §4.2 contains no new ideas.

Three things to notice in the rear-view mirror, because they all survive to the full system:

  1. The meta-gradient flowed through the inner gradient: the derivative \(d\theta_1/d\eta\) required \(\partial^2 L/\partial\eta\,\partial\theta\) — a mixed second derivative. The phrase "gradient through gradients" means exactly this: the inner update is a gradient, and we are differentiating it.
  2. The meta-gradient is the product of "where the student ended up relative to where reward lives" (\(J'\)) and "how the teacher's knob moves the student" (\(d\theta_1/d\eta\)). The teacher learns from where its students land.
  3. Nothing required \(\eta\) to be a "good target" in any pre-defined sense. If hitting \(\theta^\star\) required the target to be a systematically biased lie, gradient ascent on \(\eta\) would happily learn to lie. This is why discovered targets can have semantics that no human would design.

4.2 The general recursion: unrolling the inner loop

Now do it properly. With SGD as the inner optimizer (Adam adds bookkeeping but no new ideas — we'll come back to it), the update at inner step \(k\) is

$$ \theta_{k+1} = \theta_k - \alpha\, g_k, \qquad g_k = \nabla_\theta L(\theta_k, \eta;\,\mathcal{D}_k). $$

Differentiate both sides with respect to \(\eta\) — remembering that \(g_k\) depends on \(\eta\) both explicitly (the targets) and implicitly (through \(\theta_k\), which earlier updates shaped):

$$ \frac{d\theta_{k+1}}{d\eta} = \big(I - \alpha H_k\big)\,\frac{d\theta_k}{d\eta} \;-\; \alpha\, C_k, \qquad H_k = \frac{\partial^2 L}{\partial\theta\,\partial\theta^{\!\top}}\bigg|_{\theta_k}, \quad C_k = \frac{\partial^2 L}{\partial\eta\,\partial\theta}\bigg|_{\theta_k}. $$

This is Step 6 of §4.1, with the scalars promoted: \(H_k\) is the Hessian matrix of the inner loss (entry \((i,j)\) is \(\partial^2 L/\partial\theta_i\,\partial\theta_j\) — the curvature), and \(C_k\) is the Jacobian of the inner gradient with respect to the meta-parameters (shape \(|\theta|\times|\eta|\); entry \((i,j)\) is \(\partial^2 L/\partial\eta_j\,\partial\theta_i\) — how meta-knob \(j\) tilts the slope felt by agent-parameter \(i\)). Also \(d\theta_{k+1}/d\eta\) is itself a \(|\theta|\times|\eta|\) matrix: row \(i\), column \(j\) answers "how much does agent parameter \(i\) at step \(k{+}1\) move if meta parameter \(j\) is wiggled".

Unroll the recursion from \(d\theta_0/d\eta = 0\) (the initialization owes nothing to the teacher) and plug into the chain rule, and the meta-gradient becomes a sum over inner steps:

$$ \nabla_\eta J = -\alpha \sum_{k=0}^{N-1} C_k^{\!\top} \underbrace{\Big[\textstyle\prod_{j=k+1}^{N-1}\!\big(I-\alpha H_j\big)\Big]^{\!\top}\nabla_\theta J(\theta_N)}_{\displaystyle v_{k+1}} $$

Read it right to left, the way backprop computes it. \(\nabla_\theta J(\theta_N)\) says "in which direction should the final parameters have moved to earn more reward". Each factor \((I-\alpha H_j)^{\!\top}\) pulls that desire one update earlier — the Hessian term accounts for the fact that changing \(\theta_j\) changes the gradient the agent took at step \(j\). And each \(C_k^{\!\top}\) finally converts "the parameters at step \(k\) should have moved differently" into "the targets at step \(k\) should have been different" — which is a statement about \(\eta\). Summed over the window, the meta-network gets one consolidated lesson per meta-step: here is how you should have taught differently.

Intuition — The meta-gradient is exactly the credit-assignment question every teacher asks: "given where my student ended up, how should I have phrased my corrections along the way?" The Hessian factors are the annoying-but-essential part: they model how each correction changed the student's subsequent reaction to corrections, not just the student's state.

4.3 What this looks like inside JAX

Here's the thing that makes JAX (and the whole project) feel like magic: you don't write any of the above. You write the inner loop as plain code and call jax.grad on it. The released colab does literally this — the inner loop is a lax.scan over agent updates, and the meta-gradient is one jax.grad:

# From disco_rl's official meta_train.ipynb (abridged) ------------------
def _outer_loss(update_rule_params, agent_state, train_rollouts,
                valid_rollout, rng):
    # 1. INNER LOOP: N agent updates under the current rule.
    #    is_meta_training=True => targets are NOT stop-gradiented,
    #    so the graph from eta into each update is kept alive.
    (_, new_learner_state, ...), train_metrics = jax.lax.scan(
        _inner_step,                       # one full agent update
        (update_rule_params, agent_state.learner_state, ...),
        (train_rollouts, learner_rngs),
    )

    # 2. OUTER OBJECTIVE: run the *updated* agent on a held-out
    #    validation rollout and score it with a policy-gradient
    #    surrogate (advantage from a separate meta-value function).
    adv_t = jax.lax.stop_gradient(value_out.normalized_adv)
    pg_loss = utils.differentiable_policy_gradient_loss(
        logits_on_valid, actions_on_valid, adv_t=adv_t, backprop=False)

    # 3. Meta-regularizers (see section 4.5).
    meta_loss = pg_loss.mean() + reg_loss
    return meta_loss, aux

# The entire meta-gradient -- second-order terms included -- is one call:
meta_grads, outputs = jax.grad(_outer_loss, has_aux=True)(
    update_rule_params, agent_state, train_rollouts, valid_rollout, rng)

What does autodiff actually do with this? Mechanically, when the outer backward pass reaches an inner step, it must differentiate through the node "g = jax.grad(L)(theta, eta)". But that node is itself a little program (the backward pass of \(L\)), built of multiplications, softmaxes, LSTM cells. So reverse-mode AD simply… backpropagates through the backward pass. This is called reverse-over-reverse differentiation, and it has two consequences:

  • Compute: each VJP through an inner step implicitly forms the products \(H_k v\) and \(C_k^\top v\) — Hessian-vector and mixed-derivative-vector products. Never full matrices: for Disco103's agent (\(\sim10^7\) params), \(H_k\) would be \(10^7 \times 10^7\). Everything stays matrix-free.
  • Memory: to backprop through the inner backward pass, you must store the inner backward pass's own intermediate values — for every update in the window. This is the memory bomb that §6 defuses.

4.4 The two halves of the estimator

Half one, \(\nabla_\eta\theta\), is exact but truncated. Backpropagating through an agent's entire lifetime (hundreds of thousands of updates) is impossible, so DiscoRL backprops through a sliding window of 20 agent updates — truncated backprop-through-time, where "time" is optimization steps. Truncation makes the meta-gradient myopic: \(\eta\) gets direct credit only for what its teaching achieved within 20 updates. Two mechanisms push back against the myopia: the lifetime meta-LSTM (its hidden state persists across windows, carrying longer-horizon information forward even though gradients don't flow back through it forever), and the population itself — at any instant, different agents sit at different points of their lifetimes (their experience budgets — 200M, 100M, 50M or 20M steps, sampled with probability inversely proportional to length — guarantee it), so every meta-update averages teaching-lessons from young, middle-aged and old students simultaneously. The rule can't overfit to one life stage.

Half two, \(\nabla_\theta J\), is an RL estimator, not autodiff. You cannot differentiate the environment's reward through the simulator, so DiscoRL estimates "in which direction should the final parameters move" with the most battle-tested estimator in the book — advantage actor-critic:

$$ \nabla_\theta J(\theta) \;\approx\; \mathbb{E}\Big[\, \bar A_t \,\nabla_\theta \log\pi_\theta(a_t\,|\,s_t) \Big], \qquad \bar A = \frac{A - \mu}{\sigma}, $$

where the advantage comes from a meta-value function — a critic trained with V-trace (\(\gamma = 0.997\), TD(\(\lambda=0.95\))) that exists only to estimate meta-gradients. It is not part of the discovered rule; agents trained by Disco103 at evaluation time never see it. The normalization by lifetime-accumulated mean and standard deviation \((\mu,\sigma)\) is one of the quiet load-bearing tricks: agents live in environments whose returns differ by four orders of magnitude (Pong's ±21 vs. Atlantis's millions), and without it, the meta-gradients of loud environments would drown out everyone else. In the colab this is visible as adv_t = jax.lax.stop_gradient(value_out.normalized_adv): the advantage is a fixed coefficient; gradients flow only through \(\log\pi_{\theta_N}\) — and from there, through the 20 updates, into \(\eta\).

One subtlety worth spelling out, because it confused me at first: the surrogate is evaluated on a fresh validation rollout collected after the inner-loop window (the colab literally collects a 2×-length held-out rollout for it; the production system generates 48 fresh trajectories per meta-step). The rule is graded on generalization — "did your teaching make the student act better on data it hasn't trained on?" — not on how well the student memorized the window's own batches.

4.5 The stabilizer kit

Everything above is the textbook story. The Methods section and the code reveal what it takes to make it not explode. Each of these earns its place at scale:

TrickWhat it doesWhy it's needed
Per-agent Adam, then average
\(\eta \leftarrow \eta + \tfrac1n\sum_i \text{ADAM}(g_i)\)		 Each agent's meta-gradient goes through its own Adam normalizer before the population average. Adam's per-coordinate scale-invariance equalizes agents across environments — a second defense (after advantage normalization) against loud-environment domination.
Prediction entropy bonus
\(L_{\text{ent}} = -\mathbb{E}[H(y_\theta)+H(z_\theta)]\)		 Added to the meta-objective; rewards rules whose students keep high-entropy predictions. Prevents premature collapse: early in discovery the easiest way to minimize a KL is to make targets and predictions both trivially peaked. Dead predictions = dead search space.
Trust region on policy targets
\(L_{\text{KL}} = D_{\text{KL}}\!\big(\pi_{\theta^-}\,\|\,\hat\pi\big)\)		 Penalizes policy targets that stray far from an EMA snapshot \(\theta^-\) of the agent. The meta-net could otherwise propose arbitrarily aggressive policy jumps that score well for one window and destroy the agent after. This is a learned-algorithm analogue of PPO's clip.
Target centering (colab)
\(\big\|\mathbb{E}[\hat y]\big\|^2 + \big\|\mathbb{E}[\hat z]\big\|^2 + \big\|\mathbb{E}[\hat\pi]\big\|^2\)		 Small penalty on the mean of emitted target logits. Removes a degenerate degree of freedom (constant offsets in logit space do nothing after softmax but bloat meta-gradients).
Adam with stop-grad denominator
(optimizers.py)		 The inner Adam's update is \(\hat m/(\sqrt{\hat v}+\epsilon)\); meta-gradients flow through \(\hat m\) but stop_gradient is applied to \(\hat v\). Differentiating through the second-moment denominator adds a third second-order path that is tiny, noisy, and couples the meta-gradient to gradient scale in a destabilizing way. Cheaper and stabler to treat the preconditioner as a constant.
Agent resets + budget mixture Agents restart from scratch when their budget (sampled from {200M, 100M, 50M, 20M} steps, weights ∝ 1/budget) is consumed. Keeps the population covering all phases of learning; most learning progress happens early in a lifetime, so short lives are oversampled.
Meta-gradient clipping (1.0) and meta-Adam lr \(10^{-3}\) Standard, but on the meta level. Second-order products through 20 updates have heavy tails. One bad window shouldn't lobotomize the rule.

Note the paper's framing discipline: all of this machinery stabilizes meta-optimization only. None of it constrains how the discovered rule updates agents — the search space stays clean.

5Why KL-to-targets, not a learned loss

There were two other obvious designs, and earlier work tried both. The meta-network could output a scalar loss \(\ell_\eta(f_\theta)\) and let the agent descend it (Evolved Policy Gradients, MetaGenRL, Learned Policy Optimisation). Or it could output the parameter update directly (classic learned-optimizer style, back to Schmidhuber and Bengio). DiscoRL outputs targets, matched with a KL divergence. This choice is quietly one of the most important in the paper, and it's justified on three grounds: expressivity, conditioning, and interface.

5.1 Expressivity: targets strictly contain learned losses

Suppose the meta-net outputs a scalar loss \(\ell_\eta\big(f_\theta(s)\big)\). Whatever \(\eta\) is, the induced update direction on the prediction \(f\) is

$$ \Delta f \;\propto\; -\,\frac{\partial \ell_\eta}{\partial f}\bigg|_{f_\theta(s)}, $$

i.e., the update on predictions is always the (negative) gradient field of some scalar potential. Gradient fields are special: they are conservative (zero curl), they can't rotate, and their fixed points are extrema of the potential. But the most successful update rules in RL history are not gradient fields. Q-learning's semi-gradient

$$ \Delta\theta \;\propto\; \Big(r + \gamma \max_{a'} Q_{\bar\theta}(s', a') - Q_\theta(s,a)\Big)\,\nabla_\theta Q_\theta(s,a) $$

deliberately ignores the dependence of the bootstrap target on \(\theta\) (that's the "semi") — and as a consequence is not the gradient of any objective (under linear function approximation this is a theorem: the update's vector field has non-zero curl, so no potential function exists). The same holds for TD(\(\lambda\)), Retrace, and friends. A learned-scalar-loss search space can never contain them; it can only contain residual-gradient-style methods, which are known to be worse in practice.

Targets-plus-distance dodges this entirely. The update induced by a target is

$$ \Delta\theta \;\propto\; -\,\nabla_\theta\, D\big(\underbrace{\hat y}_{\text{treated as constant}},\, y_\theta\big), $$

and because \(\hat y\) is produced by a separate network from other quantities — including the agent's own predictions at future timesteps — this is a semi-gradient by construction. The stop-gradient that defines bootstrapping has a natural home: it lives between the meta-network's output and the agent's loss. Searching over \(\eta\) searches over a space that includes TD, Q-learning, distillation, policy gradients (the target "current policy nudged along the advantage direction" reproduces them), and — the entire point — things none of us have names for.

5.2 Conditioning: KL makes the meta-landscape walkable

Why KL specifically, and why softmax everything first? Because of what it does to both optimization problems at once. Take the policy term, with target logits \(\hat\ell\) and agent logits \(\ell\) (the agent's KL is computed between the softmaxes). The gradient of \(D_{\mathrm{KL}}(\hat\pi \,\|\, \pi_\theta)\) with respect to the agent's logits is the gloriously simple

$$ \frac{\partial}{\partial \ell}\, D_{\mathrm{KL}}\big(\hat\pi\,\|\,\mathrm{softmax}(\ell)\big) \;=\; \pi_\theta - \hat\pi . $$

Every component lives in \([-1, 1]\). The inner update literally moves probability mass toward the target distribution, with a step size that cannot blow up no matter what the meta-network emits. Contrast a learned scalar loss: nothing constrains its curvature or scale, so the meta-net controls not only the direction but the magnitude and conditioning of every inner step — a recipe for inner-loop divergence half-way through every meta-experiment. With KL-to-softmaxed-targets, the meta-network's expressive power is spent exactly where you want it (where should beliefs move) and not where you don't (how violently). The fixed loss weights (1.0, 1.0, 1.0, 0.2) and the agent's gradient clipping stay hand-controlled.

This bounded-gradient property compounds through the meta-gradient too. Look back at the recursion in §4.2: \(\nabla_\eta J\) contains products of inner-loss second derivatives. For KL of softmaxes, those Hessians are softmax covariance matrices — bounded, smooth, with no exploding directions. The paper's citation trail (this design is inherited from LPG, Oh et al. 2020) says the quiet part: KL was chosen because it "has previously been found to make meta-optimization easier." Even the value function is made categorical (601 bins, two-hot targets, MuZero-style) so that its loss is also a bounded cross-entropy rather than an unbounded squared error — every learnable quantity in the agent presents the same well-conditioned interface to the discovery process.

5.3 Interface: targets are architecture- and action-space-agnostic

The third reason is engineering-shaped but decisive for generality. A rule that outputs per-parameter updates is welded to one architecture. A rule that outputs a loss must still be differentiated, fixing what "the loss's inputs" are. A rule that outputs targets for the agent's outputs only needs the agent to have outputs — any torso (the discovery agents were small; the Atari evaluation agent was MuZero-sized, and the rule transferred), any observation space (the meta-net never sees observations, only predictions), and any action space (action-indexed inputs and outputs are processed with weights shared across the action dimension). That's also why your and my Craftax agents — architectures never seen in discovery — train fine under Disco103's frozen weights.

Ablation receipts — On Atari (IQM after discovery from 16 games): full system 11.6; remove the auxiliary prediction \(p\): 10.5; shrink the discovery agents: 8.7; remove the discovered predictions \(y, z\) entirely: 5.0; discover from toy gridworlds instead of Atari: 3.4; remove the value function: 2.9. The discovered prediction channels more than double the rule's quality, and the value function — the one predefined semantic anchor — matters most of all. Bootstrapping emerges without being asked for: perturbing the prediction \(z_{t+L}\) at a future step visibly changes the target \(\hat z_t\) today (Fig. 4d), and cutting prediction inputs off when computing targets craters performance (Fig. 4e).

6The memory wall, and MixFlow-MG

Now the part the Nature paper dispatches in one sentence ("We used MixFlow-MG to minimize the computational cost of the runs") and which deserves a whole section, because it's the difference between this experiment fitting on TPUs or not.

6.1 Where the memory goes

Reverse-mode AD's deal with the devil is: store the forward pass, get cheap gradients. For an ordinary training step you store the activations \(A\) of one forward pass. But our outer "forward pass" is twenty agent updates, each containing its own forward AND backward pass. Reverse-over-reverse differentiation must therefore store, for every inner step \(i\) in the window:

  • the activations of the inner forward pass (loss computation: agent unroll + meta-net unroll), and
  • the intermediates of the inner backward pass (the graph that computed \(g_i\)) — because the outer cotangent must traverse it, and
  • the parameters and optimizer state \((\theta_i, \upsilon_i)\) at that step.

Total: \(\mathcal{O}\big(T\cdot(|A| + |\theta| + |\upsilon|)\big)\) for a \(T\)-step window. (Notation note: this section keeps MixFlow-MG's symbols, where \(T\) counts updates in the window — the \(N\) of §4.2 — not trajectory timesteps.) The activation term dominates, and it scales like batch × unroll-length × network size. For DiscoRL's production batches (96 trajectories × 29 steps per update, ×20 updates, with an LSTM meta-net woven through every one of them), naive nesting simply does not fit. Gradient checkpointing (jax.remat) trades memory for recompute and gets you to \(\mathcal{O}(|A| + T(|\theta|+|\upsilon|))\), but the recomputation tax across a 20-step window is brutal, and the per-step backward graphs must still be materialized when their turn comes.

6.2 The reparameterization: make the gradient a first-class citizen

MixFlow-MG (Kemaev, Calian, Zintgraf, Farquhar, van Hasselt — the DiscoRL infrastructure authors) starts from a deceptively bureaucratic move. Write the inner update not as a monolithic \(\Phi\), but with the inner gradient exposed as an explicit argument:

$$ (\theta_{i+1}, \upsilon_{i+1}) = \Phi(\theta_i, \upsilon_i, \eta, x_i) = \Upsilon\big(\underbrace{\nabla L_i}_{\text{explicit!}},\; \theta_i, \upsilon_i, \eta, x_i\big). $$

Now differentiate the unrolled chain with respect to \(\eta\). The total derivative picks up exactly the terms we met in §4.2, but with the optimizer's Jacobians factored out:

$$ \frac{d\,\Upsilon_{i+1}}{d\eta} = \left[\frac{\partial \Upsilon_{i+1}}{\partial \theta_i} + \frac{\partial \Upsilon_{i+1}}{\partial \nabla L_i}\,\frac{\partial^2 L}{\partial \theta_i^2} \;,\;\; \frac{\partial \Upsilon_{i+1}}{\partial \upsilon_i}\right] \frac{d\,\Upsilon_i}{d\eta} \;+\; \frac{\partial \Upsilon_{i+1}}{\partial \nabla L_i}\, \frac{\partial^2 L}{\partial \eta\,\partial \theta_i} \;+\; \frac{\partial \Upsilon_{i+1}}{\partial \eta}. $$

In reverse mode, the expensive pieces are the cotangent products with the two second-derivative blocks: \(v^\top\!\cdot \partial^2 L/\partial\theta_i^2\) (vector-Hessian product) and \(v^\top\!\cdot \partial^2 L/\partial\eta\,\partial\theta_i\) (vector-mixed-derivative product). The naive implementation computes them by backpropagating through the stored backward graph. And here is the entire trick, in one application of Schwarz's theorem — second derivatives of a (twice continuously differentiable) function are symmetric:

$$ \frac{\partial^2 L}{\partial \theta^2} = \Big(\frac{\partial^2 L}{\partial \theta^2}\Big)^{\!\top}, \qquad \frac{\partial^2 L}{\partial \eta\,\partial \theta} = \Big(\frac{\partial^2 L}{\partial \theta\,\partial \eta}\Big)^{\!\top}. $$

So every vector-by-Hessian product equals the transpose of a Hessian-by-vector product — and Hessian-by-vector products have a famously cheap implementation that needs no second backward graph at all: forward-mode differentiation of the gradient function,

$$ \frac{\partial^2 L}{\partial\theta^2}\, v \;=\; \lim_{\epsilon\to0}\frac{\nabla_\theta L(\theta + \epsilon v) - \nabla_\theta L(\theta)}{\epsilon} \;=\; \texttt{jvp}\big(\nabla_\theta L,\; \theta,\; v\big), $$

and identically for the mixed block: \(v^\top \partial^2L/\partial\eta\,\partial\theta\) is the JVP of the function \(\theta \mapsto \nabla_\eta L(\theta,\eta)\) in direction \(v\). This is forward-over-reverse — mixed-mode — differentiation: reverse mode on the inside (one gradient), forward mode on the outside (one tangent riding along it).

# The whole of MixFlow-MG's core, in JAX:
g_fn = jax.grad(L, argnums=(0, 1))         # th -> (grad_theta L, grad_eta L)

# Naive (reverse-over-reverse): differentiate through a STORED backward graph.
#   vT_H  = jax.vjp(jax.grad(L), theta)[1](v)        # stores backward graph
# MixFlow (forward-over-reverse): push tangent v through the SAME backward pass.
_, (Hv, Mv) = jax.jvp(lambda th: g_fn(th, eta), (theta,), (v,))
#    Hv =  d(grad_theta L)/d theta . v   =  Hessian-vector product
#    Mv =  d(grad_eta   L)/d theta . v   =  mixed-derivative product
# By symmetry these EQUAL the v.(d2L/dtheta2) and v.(d2L/deta dtheta)
# that the outer backward pass needs. Same numbers, different mode.

6.3 Why forward-over-reverse is so much cheaper

The asymmetry between the modes is all about what must be remembered:

  • Reverse mode over a computation must store that computation's intermediates, because cotangents are consumed in the opposite order to how values are produced. Reverse over the inner backward pass ⇒ store the backward pass.
  • Forward mode propagates tangents in the same order as the primal computation — each intermediate tangent is consumed immediately and can be freed. Forward over the inner backward pass ⇒ store (almost) nothing extra. Cost: roughly 2× the FLOPs of the pass it rides on, which is why wall-clock improves only modestly while memory improves dramatically.

For completeness, the four ways to compose a second derivative, and why this corner wins:

ModeComputesExtra memoryVerdict
reverse-over-reverse\(v^\top H\) directlystores the inner backward graph, ×Twhat grad(grad(·)) gives you; the default; the bomb
forward-over-reverse\(Hv\) (= \(v^\top H\) by symmetry)≈ none beyond one gradient passMixFlow-MG
reverse-over-forward\(Hv\)stores the (cheap) forward-tangent passalso fine; equivalent numerics, slightly different engineering
forward-over-forwardone Hessian column per passnoneneeds \(|\theta|\) passes; hopeless

The reported results: peak memory down ~75% (4×) in typical configurations and over 90% (10×+) in large ones — converging to ~25× on TPU for Chinchilla-style transformer meta-learning — plus up to 25% faster wall-clock, with bit-identical meta-gradients. It's a pure implementation theorem: nothing about the optimization problem changes. (My toy in §7 verifies the "identical" claim to within float32 roundoff: max relative deviation ~10⁻⁷ across all meta-parameter leaves.)

Why this matters beyond DiscoRL — Nothing in MixFlow-MG is meta-RL-specific. Any bilevel problem with a gradient-based inner loop — hyperparameter optimization, MAML-family adaptation, learned optimizers, data-distillation, RLHF-through-finetuning schemes — hits the same reverse-over-reverse wall and admits the same fix. If you remember one implementation idea from this post: when you need \(v^\top\!\cdot\partial(\text{gradient})\), transpose it into a JVP of the gradient and let forward mode ride the backward pass.

7A 200-line DiscoRL you can run

Time to make all of it concrete. Below is a complete, runnable meta-training loop — blog/toy_discorl.py in the repo — that preserves every conceptual ingredient and throws away every scale ingredient. The world is a 6-state corridor: start at the left, reward 1 for reaching the right end within 10 steps, absorbing goal. A uniform-random policy succeeds 17.5% of the time. The agent is tabular — policy logits pi[6,2] and a 4-dimensional prediction y[6,4] with no assigned meaning. The meta-network is a 16-unit RNN that scans each trajectory backwards over (reward, action, \(\pi(\cdot|s)\), \(\mathrm{softmax}\,y_t\), \(\mathrm{softmax}\,y_{t+1}\)) and emits per-step targets \((\hat\pi_t, \hat y_t)\). The agent takes 8 SGD steps on \(\mathrm{KL}(\hat\pi\|\pi) + \mathrm{KL}(\hat y\|y)\); the meta-objective is the exact expected return of the final policy, computed differentiably by dynamic programming (the luxury of a 6-state MDP — this stands in for the actor-critic estimator of §4.4); and jax.grad through the whole unroll is the meta-gradient.

import functools
import jax
import jax.numpy as jnp
import optax

S, A, K_PRED, H_META = 6, 2, 4, 16   # states, actions, |y|, meta hidden size
T, B, K_INNER = 10, 16, 8            # horizon, rollouts/update, inner updates
ALPHA = 5.0                          # inner SGD learning rate
GOAL = S - 1

# ----------------------------------------------------------------------------
# Environment: chain MDP with absorbing goal.
# ----------------------------------------------------------------------------
def env_step(s, a):
    s2 = jnp.where(s == GOAL, GOAL, jnp.clip(s + 2 * a - 1, 0, GOAL))
    r = jnp.where((s != GOAL) & (s2 == GOAL), 1.0, 0.0)
    return s2, r

def rollout(theta, key):
    """Sample one trajectory. Data only -- no gradient flows through sampling."""
    pi_logits = jax.lax.stop_gradient(theta['pi'])

    def step(s, key_t):
        a = jax.random.categorical(key_t, pi_logits[s])
        s2, r = env_step(s, a)
        return s2, (s, a, r)

    keys = jax.random.split(key, T)
    s_last, (ss, aa, rr) = jax.lax.scan(step, jnp.int32(0), keys)
    states = jnp.concatenate([ss, s_last[None]])          # [T+1]
    return dict(s=states, a=aa, r=rr)

def exact_return(pi_logits):
    """Differentiable J(pi): exact probability of reaching the goal within T.
    This is the toy's stand-in for the advantage actor-critic estimator."""
    pi = jax.nn.softmax(pi_logits)
    idx = jnp.arange(S)

    def step(carry, _):
        p, j = carry
        mass = p.at[GOAL].set(0.0)                        # non-absorbed mass
        p2 = jnp.zeros(S).at[jnp.clip(idx + 1, 0, GOAL)].add(pi[:, 1] * mass)
        p2 = p2.at[jnp.clip(idx - 1, 0, GOAL)].add(pi[:, 0] * mass)
        r = p2[GOAL]                                      # newly absorbed mass
        p2 = p2.at[GOAL].add(p[GOAL])
        return (p2, j + r), None

    p0 = jnp.zeros(S).at[0].set(1.0)
    (_, j), _ = jax.lax.scan(step, (p0, 0.0), None, length=T)
    return j

# ----------------------------------------------------------------------------
# Meta-network: backwards RNN over the trajectory -> targets (pi_hat, y_hat).
# ----------------------------------------------------------------------------
def init_eta(key):
    f = 1 + A + A + 2 * K_PRED                            # per-step features
    k1, k2, k3, k4 = jax.random.split(key, 4)
    g = lambda k, shape, s: s * jax.random.normal(k, shape)
    return dict(Wx=g(k1, (f, H_META), 0.3), Wh=g(k2, (H_META, H_META), 0.3),
                b=jnp.zeros(H_META),
                Wpi=g(k3, (H_META, A), 0.1), Wy=g(k4, (H_META, K_PRED), 0.1))

def meta_targets(eta, theta, traj):
    s, a, r = traj['s'], traj['a'], traj['r']
    pi_p = jax.nn.softmax(theta['pi'][s[:-1]])            # [T, A]
    y_p = jax.nn.softmax(theta['y'][s])                   # [T+1, K]
    # Inputs are treated as data w.r.t. theta (cf. stop_grad input transforms).
    pi_p, y_p = jax.lax.stop_gradient((pi_p, y_p))
    feats = jnp.concatenate(                              # [T, F]
        [r[:, None], jax.nn.one_hot(a, A), pi_p, y_p[:-1], y_p[1:]], axis=-1)

    def cell(h, x):                                       # h carries the FUTURE
        h = jnp.tanh(x @ eta['Wx'] + h @ eta['Wh'] + eta['b'])
        return h, h

    _, hs = jax.lax.scan(cell, jnp.zeros(H_META), feats, reverse=True)
    return hs @ eta['Wpi'], hs @ eta['Wy']                # target logits

# ----------------------------------------------------------------------------
# Agent loss: KL(targets || predictions), gradients flow into eta via targets.
# ----------------------------------------------------------------------------
def kl(p_logits, q_logits):
    p = jax.nn.softmax(p_logits)
    return jnp.sum(p * (jax.nn.log_softmax(p_logits)
                        - jax.nn.log_softmax(q_logits)), axis=-1)

def agent_loss(theta, eta, traj):
    pi_hat, y_hat = meta_targets(eta, theta, traj)
    s = traj['s'][:-1]
    return jnp.mean(kl(pi_hat, theta['pi'][s]) + kl(y_hat, theta['y'][s]))

def batched_loss(theta, eta, trajs):
    return jnp.mean(jax.vmap(agent_loss, in_axes=(None, None, 0))(
        theta, eta, trajs))

def init_theta():
    return dict(pi=jnp.zeros((S, A)), y=jnp.zeros((S, K_PRED)))

# ----------------------------------------------------------------------------
# Meta-objective: unroll K_INNER agent updates, return -J(theta_K).
# jax.grad of this is the meta-gradient (reverse-over-reverse by default).
# ----------------------------------------------------------------------------
def unroll_inner(eta, key, step_fn):
    theta = init_theta()
    for _ in range(K_INNER):
        key, sub = jax.random.split(key)
        trajs = jax.vmap(rollout, in_axes=(None, 0))(
            theta, jax.random.split(sub, B))
        theta = step_fn(theta, eta, trajs)
    return theta

def sgd_step(theta, eta, trajs):
    g = jax.grad(batched_loss)(theta, eta, trajs)
    return jax.tree.map(lambda p, gi: p - ALPHA * gi, theta, g)

def meta_loss(eta, key):
    theta = unroll_inner(eta, key, sgd_step)
    return -exact_return(theta['pi'])

That's the entire discovery method. The meta-training loop is just Adam on jax.grad(meta_loss) with global-norm clipping at 1.0 (same as the real system). Run it:

Honest footnote — In this toy, the prediction channel \(y\) stays near-uniform after meta-training: the corridor is solvable with policy targets alone, so the rule never needs to invent prediction semantics, and the probe prints confirm it. If you want to watch \(y\) come alive, stretch the chain past the meta-net's horizon, randomize the goal position so the policy can't memorize it, or hide state. That is, rebuild in miniature the reason the real thing was discovered on Atari + ProcGen + DMLab and not on gridworlds — the paper's "toy environments" ablation (IQM 3.4 vs 11.6) is exactly this phenomenon at scale.

7.1 The MixFlow step, concretely

Part two of the script re-runs one meta-gradient with the inner step wrapped in a custom_vjp that implements §6 by hand — the backward rule does one forward-over-reverse JVP of the inner gradient function and assembles both second-order products from it:

def make_mixflow_step(trajs):
    def inner_grad(theta, eta):                  # th -> (grad_th L, grad_eta L)
        return jax.grad(batched_loss, argnums=(0, 1))(theta, eta, trajs)

    def primal(theta, eta):
        g_theta = jax.grad(batched_loss)(theta, eta, trajs)
        return jax.tree.map(lambda p, gi: p - ALPHA * gi, theta, g_theta)

    @jax.custom_vjp
    def step(theta, eta):
        return primal(theta, eta)

    def fwd(theta, eta):
        return primal(theta, eta), (theta, eta)

    def bwd(res, v):                             # v = dJ/d theta_{k+1}
        theta, eta = res
        # ONE forward-over-reverse JVP gives both second-order products:
        #   Hv = (d2L/dth2) v          (Schwarz: == v.(d2L/dth2))
        #   Mv = (d2L/dth deta)^T v    (Schwarz: == v.(d(grad_th L)/d eta))
        _, (Hv, Mv) = jax.jvp(lambda th: inner_grad(th, eta), (theta,), (v,))
        v_theta = jax.tree.map(lambda a, b: a - ALPHA * b, v, Hv)   # (I-aH)^T v
        v_eta = jax.tree.map(lambda b: -ALPHA * b, Mv)              # -a C^T v
        return v_theta, v_eta

    step.defvjp(fwd, bwd)
    return step

Note how bwd is a line-for-line transcription of the reverse recursion from §4.2: \(v_{k} = (I - \alpha H_k)^\top v_{k+1}\) continuing left, \(-\alpha\,C_k^\top v_{k+1}\) deposited on \(\eta\). The script checks the result against the naive nested jax.grad and gets agreement to ~\(10^{-7}\) relative — float32 roundoff — which is the Schwarz-symmetry guarantee made empirical. In the toy the memory win is invisible (everything is tiny); at DiscoRL's batch sizes it's the whole ballgame.

8What the toy hides: the real system at full size

A few production facts worth keeping in your head when you reason about extensions, all from the Methods section and the released config:

  • Scale of discovery. Disco57: 128 agents cycling the 57 Atari games, 1024 TPUv3 cores, 64 hours. Disco103: 206 agents over Atari + ProcGen + DMLab-30, 2048 TPUv3 cores, 60 hours. The best rule emerged after about 3 simulated lifetimes per game (~600M steps/game) — cheaper than the hyperparameter sweeps most labs run to tune a hand-designed agent, which is the efficiency argument hiding inside the paper.
  • The rule transfers up. Discovery used small agents; evaluation used MuZero-sized networks (4 residual conv blocks of 256/384/384/256, 768-d FC, 1024-d LSTM). The rule survived the size jump, plus replay-ratio and optimizer sweeps (Extended Data Fig. 1) — robustness that hand-designed algorithms often lack.
  • Data > architecture, again. Swapping the meta-LSTM for a transformer: no significant change (Extended Data Fig. 3). Growing the environment set from 14 → 103: monotone improvement on held-out ProcGen (Fig. 3b). The paper's closing claim — the discovered rule's quality is a function of the data (environments) and compute poured into discovery, not of meta-architectural cleverness — is the bitter lesson, now operating one level up.
  • And it generalizes. Disco57, discovered purely on Atari, was SOTA on ProcGen (which it never saw), placed 3rd-equivalent on the NetHack NeurIPS Challenge leaderboard without domain knowledge, and Disco103 hits human-level Crafter and near-MuZero Sokoban. Held-out generalization is the headline result; everything in §4–§6 is the machinery that bought it.

9Where I'd push next

If DiscoRL's lesson is "the update rule is learnable", the obvious follow-up is: what's still hand-designed, and what happens when each piece falls? Ranked roughly by how tractable I think they are from where the code stands today:

  1. Learn the optimizer. The inner Adam (β₁, β₂, the stop-grad denominator, clipping, the learning rate itself) is hand-picked and frozen. The cleanest first experiment: give the meta-network a second output head that modulates a per-update step-size (or per-head step-sizes) from the same lifetime-LSTM state that already tracks learning dynamics. The MixFlow-MG reparameterization \(\Upsilon(\nabla L, \theta, \upsilon, \eta)\) is already the right abstraction — the optimizer is just another differentiable block between gradient and parameters, begging for \(\eta\) to reach into it.
  2. Learn the exploration. Agents act by sampling \(\pi\); nothing lets the rule ask for information. Expose the behavior policy as a meta-network output (a target for an exploration head, say), and the rule can discover its own intrinsic-motivation scheme. The paper's analysis already shows \(y\) spiking before salient events — the rule built a surprise detector; it just has no lever to act on it.
  3. Unfreeze the meta-objective. Today the outer loss is hand-designed: discounted return, γ=0.997, V-trace advantages, entropy regularizers. That's a human prior on what learning is for. Options going up the ladder: meta-learn the outer discount/regularizer weights (gradients through gradients through gradients — the same recursion, one level deeper, and MixFlow composes); or replace lifetime return with regret-style or area-under-curve objectives that reward fast learning rather than final performance.
  4. Break the 20-update horizon. Truncated windows make the rule myopic about its own long-term effects (e.g., teaching representations that pay off millions of steps later). Three escape routes: (a) implicit differentiation at approximate inner fixed points — cheap but assumes stationarity that RL agents don't have; (b) hybrid ES-plus-gradients: evolution strategies give unbiased lifetime-horizon meta-gradients while the backprop term gives variance-reduced local detail (and ES needs no second-order memory at all); (c) lean harder on the lifetime meta-RNN: its state already spans whole lives — train richer summaries into it so the truncated window can "see" the past it can't differentiate through.
  5. Make the environment distribution a player. Fig. 3b is a scaling law in environments. Hand-curating 103 of them was explicitly not needed ("we simply used popular benchmarks") — which suggests the next multiplier is an automatic curriculum: a generator that proposes worlds where the current rule learns worst (POET-style open-endedness, or generative world models as the environment factory). Discovery compute then buys not just a better rule but a better distribution of teachers for the rule.
  6. Distill the rule into something we can read. Disco103 is 600-dim targets from an LSTM — a superb artifact and a terrible textbook. Symbolic regression / program distillation over the meta-net's input-output behavior (fit closed-form target formulas to its targets across regimes, then ablate) could extract the human-readable core: how does its bootstrapping differ from TD(λ)? what is the discovered \(y\)-semantics in equations? I've started poking at this on a research branch of my Craftax repro, and it feels like the highest-leverage science per GPU-hour available here: the discovery loop found something; the distillation loop tells us what.
  7. Self-referential closure. The end state Schmidhuber kept writing about: the rule that improves the rule. Concretely imaginable now — the meta-optimization step (Adam on \(\eta\), the window length, the population aggregation) is itself a differentiable program, so a meta-meta-network could produce its targets. The recursion in §4.2 doesn't care how many levels it has; memory does (each level multiplies the MixFlow problem), and stability really does. Before the full ouroboros, a modest version: use Disco-style discovery to learn the rule for training meta-networks — bootstrapping the discovery process with its own product once is the two-level proof of concept.
The one-sentence version — DiscoRL demonstrated that "experiences of agents → gradient → better learning rule" is a working pipeline; every hand-set knob that remains (optimizer, exploration, objective, horizon, environment set, and the discovery loop itself) is now a target for the same move, and the calculus in §4 plus the memory trick in §6 is exactly the toolkit each of those moves will need.
